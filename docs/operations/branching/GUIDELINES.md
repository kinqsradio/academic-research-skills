# Branching procedures

Keep reusable instructions for template, research, and maintenance branches here. Start with [the branch workflow](branch-workflow.md), which owns promotion, naming, and attribution policy. Use [paired skill synchronization](skill-synchronization.md) for every reusable skill change, its public/private publication gates, and propagation to active private research branches. Use [the contribution walkthrough](contributing-changes.md) for public fork and PR steps, contributions from private or template-created projects, and reviewed imports back into private workspaces. Root [CONTRIBUTING.md](../../../CONTRIBUTING.md) owns public contribution scope and entrypoints.

Put project-specific branch audits or decisions on the relevant `research/<project>` branch in their appropriate records, not in the reusable template procedure. Keep public contribution history separate from private research history.
