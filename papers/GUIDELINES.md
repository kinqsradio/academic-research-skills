# Downloaded papers

This folder stores local papers downloaded by agents or supplied by researchers. Research PDFs must stay ignored and must never be staged, committed, or pushed on any branch, including project branches. Git tracks the folder guidance and metadata registers, not research PDFs. Preserve the downloaded document; put summaries and analysis in docs/literature/, not inside source PDFs.

For every download attempt, update [DOWNLOADS.md](DOWNLOADS.md). For each successful download, also add or update its IEEE reference in [REFERENCES.md](REFERENCES.md) in the same task. Record a stable local ID, relative filename, verified title, authors, year, DOI or landing URL, actual retrieval URL and date, downloader, version, full-text availability, file size in bytes, and SHA-256 checksum for each successfully verified local PDF. Use checksum and size to identify the exact downloaded bytes; bibliographic identity alone does not distinguish versions. Leave legacy checksum or size fields unknown unless actually computed. Retain bibliographic evidence locators (PDF page and title/author/publication block, or primary publisher/repository metadata). Record missing fields as unknown; a landing URL is not evidence of the historical download route. Check that a supposed PDF is readable and is the intended paper, not an error or login page.

Use the [official IEEE Reference Guide](https://journals.ieeeauthorcenter.ieee.org/wp-content/uploads/sites/7/IEEE_Reference_Guide.pdf), linked by the [IEEE Author Center](https://journals.ieeeauthorcenter.ieee.org/your-role-in-article-production/ieee-editorial-style-manual/), for formatting. Keep stable source IDs separate from numbered citations. Manuscript references are numbered by first citation within that manuscript, and repeated citations reuse their number; catalog order does not dictate manuscript order. Do not present unresolved bibliographic fields or template placeholders as verified IEEE metadata.

Deduplicate by DOI and verified identity before downloading another copy. Record versions such as arXiv preprint, accepted manuscript, and published article explicitly; a DOI match alone does not establish identical text. Keep one stable ID for the same work, register additional versions as additional file/version rows under that ID, and preserve the version-specific reference/evidence. Allocate the next unused P-number for a distinct work; never recycle an ID or renumber existing IDs. Check linked corrections or retractions before relying on an article's findings, and retain unresolved status visibly.

Keep existing numbered filenames unchanged. Their labels are not verified citation metadata. For new downloads use a consistent readable name such as `author-year-short-title.pdf`; keep the source ID stable if a filename later changes. Access failures belong in the register as failures, not successful downloads. Use permitted access routes and do not bypass access controls.

Research notes should link back here by stable source ID and repository-relative local path. Keep `DOWNLOADS.md` and `REFERENCES.md` as persistent versioned metadata on the research branch; keep their template scaffolds empty on `main`. Preserve source IDs, references, provenance, and evidence notes when a local PDF is missing or removed. A fresh clone has metadata but no research PDFs: record local availability accurately and use the recorded DOI, landing page, or retrieval URL through permitted routes to retrieve copies. Verify source identity, version, size, and checksum where recorded; record a changed checksum as a different file/version rather than silently substituting it. Retain unavailable-source records and their evidence limits. Register membership and an earlier full-text reading do not prove current local availability. Distribution rights do not override the rule excluding research PDFs from Git.
